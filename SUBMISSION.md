## Start-up state (reset)

The register file, the RAM, the PIO instruction memory and the PIO FIFO memory have no reset on silicon. The tests start
them with random contents: `make RANDOM_INIT=<seed>` (cocotb, in `test/`) and `make benches RANDOM_INIT=<seed>` (Icarus
benches); the list of registers is generated by `tools/gen_random_init.py`. The seeds run in CI are listed in
`.github/workflows/pio-tests.yaml`. A program must still write a register, RAM byte or PIO word before reading it.

## Known limits (stated honestly)

- Not tested on silicon or an FPGA board for the C and 7-segment examples; they ran on the RTL compiled to WebAssembly.
- No formal verification yet. No constrained-random protocol tests.
- Pads of the CMOS5L process are not characterised yet (organisers' statement); external QSPI flash / PSRAM timing is untested on hardware.
- Only the smoke and signature PIO tests run on the placed (gate-level) netlist.
- A design that is deselected loses its state; the program has to be loaded again.
